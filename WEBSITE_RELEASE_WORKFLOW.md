# Website release layout and update rule

This is the agreed structure for future Tennis Score Wizard website work. Keep it with the website repository so the rule survives individual chats and releases.

1. Prepare each substantial app release on its own website feature branch. Its customer-facing English copy describes the target version as already released; do not label it "preview" merely because the branch is unpublished. Approval controls when the branch is merged and published.
2. Put a short link to the current release in the hero, followed by exactly one **current-release spotlight** immediately after the Pro/Standalone choice. Use the spotlight for the two or three most interesting user-facing changes, not a complete changelog.
3. Keep full feature explanations in their permanent thematic sections: Watch scoring with Watch scoring, Time Machine with replay/history, sharing with sharing, and so on. The spotlight links to those sections. A release should add or update the appropriate section without shuffling unrelated sections or removing established content.
4. Product Updates is an append-only release archive. Add the newest Pro and Standalone entries first; preserve earlier version numbers, release text, and screenshots. When a later release arrives, replace the spotlight with that release and keep still-relevant older features in their thematic sections.
5. A build-number-only fix does not automatically earn a new homepage spotlight. Describe user-visible changes in Product Updates when appropriate; use the spotlight for a substantive release or feature.
6. For videos, use a static poster and click-to-play controls. No autoplay, no unexpected sound, and no video download before interaction (`preload="none"`). Keep only a small number of short, optimized videos in the spotlight; include captions, an image fallback, and the same core information in text. Test loading and layout on narrow and wide screens.
7. Use real app captures or clearly identified deterministic demo matches. Audit each screenshot against the target release, preserve its original source capture, and replace only images whose depicted interface or meaning changed. Never imply missing point/workout data was recorded. A live heart-rate number may be described when a workout is active; decorative animation must not be claimed to match individual heartbeats.
8. Work English-first, then copy the approved structure and media decisions into the other languages. Before publishing, check links, images, responsive layout, accessibility, localization parity, and the App Store version labels. Do not silently merge an English-only layout while locale parity checks still fail; resolve the rollout choice with the user.

For Pro 2.0 / Standalone 2.0, the hero link and current-release spotlight lead with the refreshed Watch scoreboard, sound, visible live heart-rate number, and Time Machine. The permanent Time Machine section remains after Match Flow; the historical manual-match and season-recap sections stay in place.
